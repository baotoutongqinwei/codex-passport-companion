# Mac 配套应用

原生窗口是 USB、蓝牙固件的新手入口。已有 Wi-Fi 命令行和独立离线固件保留，见
[模式选择](codex-modes.zh_CN.md)。P1 功能需配套新版 Mac 程序与固件，其他想法见[优化清单](codex-improvements.zh_CN.md)。

## 首次使用

1. 使用 Apple 芯片、macOS 15 或更新版本的 Mac，安装 Codex 并登录已有 ChatGPT 账户。
   可用能力取决于 Codex 版本与账户；配套程序不提供订阅或无限额度。
2. 解压并打开 `Codex Passport.app`，可移到“应用程序”。打包版不需要 Python、ESP-IDF、
   CMake 或终端。本免费构建只有临时签名，未经 Apple 公证。其他 Mac 可能阻止打开，
   请按系统正常校验流程操作或联系管理员，不要关闭安全防护。
3. 查看 Codex/账户检查。可选 base 模型约 142 MB；选择已有的 `ggml-base.bin` 可直接
   复用而不复制，也可在窗口里下载。导入和下载均校验 SHA-256。没有模型时仍可查看
   时间、额度、对话，但暂不能语音输入。
4. 选择与已刷固件一致的 USB 或蓝牙并连接。USB 使用数据线；蓝牙需打开卡片，并按
   系统提示允许本程序访问蓝牙。首次配对在 Mac 输入卡片上的六位码。有多张卡片时，
   只打开目标卡片，或用命令行 `--address` 指定。
5. 保持应用和 Mac 运行。卡片息屏用功能键唤醒；独立电源键会切断供电，Mac 休眠也会暂停服务。

新版窗口/命令行程序只允许一份占用卡片。旧诊断脚本没有互斥锁，须检查草稿/队列后先关闭。
程序不会自动下载模型或调用付费识别服务。

## 窗口与图标

0.9.2 沿用原生 macOS 六页布局：左侧选择“连接卡片”“语音模型”“提醒设置”“固件烧录”“设备信息”或“诊断控制台”。
连接页集中显示设备、Codex 与账户状态；语音页安装或复用模型；提醒页提供开关和免打扰时段。
底部始终保留当前状态及错误说明，切换页面不会断开连接。界面随系统切换深浅外观，
中文使用 macOS 系统字体。薄荷绿卡片图标用于 Dock、Finder 和窗口品牌区域。

新增设备信息页需更新 Mac 应用并烧录匹配的 0.5.0 固件，才能读取卡片数据。
替换前处理当前录音和未发送草稿，再正常退出旧程序。模型路径和提醒设置保留在原数据目录。

## 诊断控制台（桌面 0.6.0）

第六页在内存中显示连接变化、卡片请求类别／状态码和错误。成功的状态／设备轮询每 30 秒
最多记录一条，音频块不写入记录；最多保留最近 160 条，退出应用后消失。不记录或导出
对话文字、语音内容、请求 ID、令牌或 Wi-Fi 密码。

连接 USB 或已认证蓝牙卡片并刷入 0.7.0 固件后，可选择四项卡片原生只读命令：设备概况、
电池／温度、内存／任务、固件身份。卡片在已有通信任务中执行，沿当前连接回传有长度限制的
结果。一次只允许一条命令，30 秒没有回传会提示超时。旧固件仍可显示连接事件，但不能
响应这些命令。独立离线版仅通过 USB 接受校时，不提供诊断命令；Wi-Fi 命令行模式不提供这个桌面页面。
控制台不执行任意 Mac 终端命令。

## 在窗口中烧录固件

1. 打开“固件烧录”，选择内置的蓝牙、USB、离线或 Wi-Fi 版，也可选择本地合并 `.bin`。
   Wi-Fi 仍需既有命令行配网和 TLS 服务，这一页没有增加图形化 Wi-Fi 配置。
   烧录本身不需要登录 Codex、不需要语音模型，也不会发起网络请求。
2. 卡片开机，用 USB 数据线连接 Mac，点击“扫描”，核对端口和序列号。多张卡片必须手动选择；
   蓝牙连接不能用于烧录。
3. 更新时保持“保留配对与配置”开启。应用会读取分区表，完全一致才分段写入引导、分区表和应用，
   不写 NVS／PHY 区域。首次安装或分区不兼容时，可主动取消保留，并确认配对、Wi-Fi 等配置将重置。
   该方式从 `0x0` 写入合并固件，不是整片擦除。
4. 核对确认框中的固件版本、SHA-256、设备与配置影响，再开始。存在录音、草稿或跟踪中的队列时禁止烧录；
   程序会等待现有请求结束、暂停连接、检查独占锁，再核对 ESP32-C3 型号和 8 MB Flash。
5. 写入和哈希校验完成前请保持 USB 连接。成功后卡片重启，回到“连接卡片”选择新烧录的模式。
   可以在烧录页打开本地记录。失败时先查看提示与记录，再重试；程序不会自动重复写入。

桌面 0.8.0 烧录离线 0.9.0 后会等待卡片重启并自动发送 Mac 当前时间。保持桌面程序运行时，
以后用 USB 数据线连接／重连离线卡片也会自动校时，约每小时再校一次以修正漂移。
桌面端先确认卡片返回离线模式标识，才传 UTC 毫秒时间戳；卡片固定显示 UTC+8。
校时不需要 Codex 登录、语音模型或网络。若提示“暂未收到校时确认”，固件本身已烧录成功，
保持 USB 连接待程序重试；旧离线固件不支持自动校时，仍可用按键手动设置。

## 草稿待机与额度故障（桌面 0.9.1、固件 0.10.1）

草稿确认页无操作 60 秒后息屏，草稿保留；任意功能键仅唤醒，随后再次确认才发送。
草稿等待确认和 Mac 转写期间继续电量采样、设备监控与补传；录音准备、采集、收尾和发送时暂缓。
额度读取失败时，对话与草稿继续更新。额度页标明旧值或不可用，保留真实更新时间，约 30 秒后重试。
发送前始终重新检查额度，无法读取时保留草稿，不发送也不入队。

## 全版本电量历史（桌面 0.9.0、固件 0.10.0）

四种固件都在卡片开机时记录电量和电压，断开连接或自动息屏后继续。蓝牙、USB 通过正常
连接补传，Wi-Fi 通过已认证的 TLS 配套服务补传；离线版沿用 USB 自动导入，无需 Codex、
网络或语音模型。录音准备、采集、收尾和发送期间暂缓采样、Flash 写入和补传，旧读数不会标成新的采样时间。
保留配置且分区兼容地切换版本时，共用同一份 NVS 日志与出厂卡片标识。设备信息页显示最近一条读数和最多一小时内的
电量计下降值，点击“打开 CSV 记录”查看完整数据。打包应用的文件位于
`~/Library/Application Support/CodexPassport/battery-history.csv`；源码运行时默认位于
项目 `.local/battery-history.csv`，也可由 `PASSPORT_DATA_DIR` 指定。文件只在本机保存，
重复导入不会重复追加同一卡片记录。

Wi-Fi 命令行与正式桌面图表共享记录时，启动前设置
`PASSPORT_DATA_DIR="$HOME/Library/Application Support/CodexPassport"`；Wi-Fi 配置和 TLS 文件
仍使用项目原位置。同一时刻只有一个配套服务占用通信，桌面仍可查看图表。每批最多 16 条，
Mac 成功保存后才确认；重连后补传，完整补传后每五分钟再次核对，支持配套服务重启。
服务运行后，账户／额度读取失败不影响独立的电量上传。旧配套服务可能拒绝新接口，
卡片仍继续记录并稍后重试。

正常每五分钟采样，低电量或突然下降时更密集；环形缓冲最多 192 条。
卡片未从 Mac 校过时，CSV 的 `recorded_utc` 和 `recorded_utc8` 留空，仍保留开机秒数。
硬件未提供已确认的充电状态／电流读数，页面只显示电量计与电压，
“近一小时下降”是读数变化，不等于实测放电电流。完整规则见[离线版说明](codex-modes.zh_CN.md#拔线电量记录离线固件-090)。

### 电量图表（桌面 0.8.1）

在“设备信息”点击“电池 · 查看历史”，或在硬件详情下方点“查看电量图表”。原生窗口跟随
Mac 亮暗主题，直接读取已有本机 CSV，无需新增依赖。可选择卡片，以及最近 24 小时（每柱
15 分钟）或 7 天（每柱 2 小时）。每柱取区间内最后一次真实读数，缺失区间留白。点击柱子
查看 UTC+8 时间、百分比和电压；0% 仍显示，≤20% 标红，并显示最近读数与时段最低电量。

窗口打开时约每十秒检查文件变化，后台读取避免阻塞界面；不同卡片分开展示。未校时、
格式错误和未来时间的记录不绘制，并显示跳过数量，重复导入不重复计数。图表不推断充电、
不填补空档、不估算剩余续航。7 天是桌面查看范围，卡片仍受 192 条缓存限制。
全版本采集和补传需固件 0.10.0；仍兼容离线 0.9.0 的 USB 导入。

仅支持项目标准布局：NVS 位于 `0x9000`、PHY 位于 `0xF000`、factory 应用位于 `0x10000`。
拒绝单应用镜像、超限、损坏、错误芯片、自定义分区和带额外数据的固件；同时检查两个 ESP 镜像的
校验和、SHA 摘要及分区 MD5。完整性校验不代表导入文件来自官方，请选择可信来源。
确认期间保留已校验的字节快照，避免文件变化后写入另一份内容。固件操作期间阻止正常退出应用。

内置工具为未修改的 [esptool 4.12.0](https://github.com/espressif/esptool/tree/v4.12.0)，
使用 GPL-2.0-or-later 许可证。工具与依赖许可证放在应用的 `Contents/Resources/licenses`。
固件二进制属于构建产物，不进入源码 Git。

## 录音、对话和提醒

| 功能 | 使用方法与边界 |
| --- | --- |
| 录音反馈 | 长按中键，等“正在录音”再说话；准备、就绪、传输、识别各有文字和颜色。音量条是相对输入强度，不是分贝测量。第 006 批固件在停顿时也保持“正在聆听”，不再仅凭音量评价说话质量。松开后仍须预览并确认发送，准备期间松开会取消。 |
| 最近对话 | 每页三条，按 Codex 的真实交互时间 `recency_at` 排序。展示处理中、需电脑处理、执行出错和当前程序跟踪的待处理语音条数。需要支持该排序的 Codex 版本。 |
| 卡片未读 | 程序首次观察建立基线；之后助手回复变化才标记未读。在亮屏的对话最新一页显示该版本后清除；不修改 Codex 桌面已读状态。重启 Mac 配套程序后重新建立基线。 |
| 任务提醒 | 完成或需要电脑处理时，顶部短暂显示六秒；息屏时亮屏六秒，不切换当前页面。最多每 30 秒一次，最多暂存 8 条，等待超过 90 秒丢弃；相同任务事件不重复播报。 |
| 设置 | Mac 窗口可关闭卡片任务提醒、开启提示音或调整免打扰时段。默认显示提醒、声音关闭、UTC+8 22:00–08:00 免打扰；起止相同表示全天免打扰。开关立即生效，输入时间后点“保存时段”。 |
| 声音 | 可选的录音就绪短鸣在采集前播放；开始前清理麦克风缓冲。任务提示音和录音共用同一音频工作任务，录音期间不播放。免打扰也关闭录音短鸣。 |

观察范围是当前列表三条、当前对话、最近打开的八个对话（后台轮询），并非所有 Codex
对话的全局监控。内容缓存五秒，状态可能有几秒延迟。提醒是辅助提示：录音、草稿等待确认、
免打扰、关闭提醒期间不补播；已取出的提醒即使断线丢失也不重播。未读与提醒队列只保留在
Mac 程序内存中，未读标记仍是查看漏读回复的入口。权限操作继续在电脑完成。

提醒设置保存到私有 `alerts.json`，只含开关和时段，不含对话内容。Wi-Fi 命令行程序使用其
数据目录中的同名设置；与窗口共享设置时使用相同 `PASSPORT_DATA_DIR`，更改后重启命令行。
独立离线固件保留时钟、番茄钟和秒表，不包含 Codex 的录音、对话及提醒。

## 恢复与数据

### 设备信息与固件比对（0.5.0）

第五个侧栏页面展示已连接 USB／蓝牙卡片的读数，向下滚动查看硬件详情。Mac 应用和卡片
均升级到 0.5.0 后才能读取；旧固件仍可使用，但显示版本未知／等待上报，不编造读数。
本批包含第 006 批的“正在聆听”修复。Wi-Fi 和离线固件暂不上报监控数据。

| 读数 | 含义 |
| --- | --- |
| 硬件 | ESP32-C3 修订版、核心数、配置 CPU 频率、实际 Flash 容量、PSRAM 容量、屏幕尺寸和板级外设型号；静态 SRAM／RTC 规格与实测堆使用量分开显示。 |
| 内存 | 内部可逐字节访问堆的已用／空闲、开机以来最小空闲和最大连续空闲块。分母是可分配堆，不是整颗物理 SRAM，不含静态／保留内存。 |
| 存储 | 应用镜像字节数相对于应用分区容量；另列 Flash 芯片容量。NVS 展示已用／空闲／总条目，不是文件存储字节数。 |
| 电池 | 复用 BSP 读取 CW2017 电量百分比和电压；读取失败明确显示不可用。 |
| 温度 | 通过 BSP 读取可选的 ESP32-C3 芯片内部温度，配置范围 10–80 °C；不是环境或电池温度，每次读取后关闭传感器。 |
| 运行 | 本次开机时长、复位原因、任务数与通信任务最小栈余量；蓝牙支持 RSSI，USB 不适用信号强度。 |

固件 0.6.0 起由卡片 UI 工作循环在 LVGL 锁外约每五秒采样，卡片显示与 USB／蓝牙上报
共用同一份同步缓存，连接任务只做序列化。录音准备、采集、收尾和发送期间暂停，界面标注采样时间和
断线／暂停状态，重新连接时清除上一设备的样本。不包含录音、账户或对话内容；没有
HTTP 监控接口、云端上传、历史数据文件或新增监听端口。
CPU 占用、充电状态／电流、电池温度和功耗不冒充实测值。

[乐鑫芯片数据手册](https://www.espressif.com/sites/default/files/documentation/esp32-c3_datasheet_en.pdf)
给出 400 KB SRAM（含 16 KB 缓存）与 8 KB RTC SRAM；这是芯片规格，不是额外可用堆。

优先比对所选本地镜像，未选择时比对同模式内置固件，区分可升级、相同构建、卡片版本
更高、同版本不同构建、切换模式与无法判断。内置版本不代表 GitHub 最新发布版；只对
纯数字语义版本排序，旧 Git 描述保持未知，使用 ELF 哈希识别具体构建。
“查看升级”会进入现有烧录页并选择相应内置模式，不自动写入。旧固件需要先升级一次，
之后才能上报版本。

固件版本由根目录 `CMakeLists.txt` 的 `PROJECT_VER` 维护，发布更新时应递增；嵌入的
`CPFW1` 模式标识、应用版本和 ELF 哈希共同生成经过校验的桌面固件目录。同版本重新
构建可能得到不同镜像，不会被静默判为更新版本。

### 连接与恢复行为

| 情况 | 行为／处理方式 |
| --- | --- |
| 蓝牙临时断线／卡片重新开机 | 只重连原卡片，重试间隔从 1 秒逐步延长到 15 秒。 |
| 录音中断 | 丢弃不完整音频，重连后重新录音。 |
| 已识别草稿／跟踪中的队列 | 在同一进程内跨重连、暂停保留，不自动发送或重复入队。 |
| 发送回执丢失 | 保留请求去重，结果不确定时在桌面确认，不自动重试。 |
| 蓝牙关闭／权限被拒 | 停止并指出系统设置或管理员处理方式，解决后再次连接。 |
| 配对失败 | 连续三次连接/配对失败后暂停。检查六位码；若 Mac 忽略过卡片，可在卡片连接说明页清除配对后重试。 |
| 协议不匹配 | 停止并提示使用匹配固件；用户可主动进入 USB 烧录页，程序不会自动烧录。 |
| 额度后台不可用 | 保持连接，定期重读状态并明确报错，不编造额度。 |
| 暂停 | 等待当前 RPC 完成后断开，保留草稿，丢弃未完成录音。 |
| 退出 | 有录音、未发送/不确定草稿或跟踪中的队列时提示。退出会清空内存状态，不会撤回已交给 Codex 的消息。 |

打包版数据位于 `~/Library/Application Support/CodexPassport`。`voice.json` 可引用校验过
的外部模型路径，不含对话内容。开发时可通过 `PASSPORT_DATA_DIR` 选择已有私有数据目录。
临时音频在转写完成或中断后删除。仍使用本机 Whisper base 加简体转换，窗口版不开放网络
监听端口。原有命令行使用方法与固件按键保持不变。

## 构建与验证

开发者在 `.local/transport-venv` 中安装 `bridge/desktop-requirements.txt`，并通过
`tools/bootstrap_bridge.py` 准备固定版本的 CPU 引擎。
先在已激活的 IDF 环境执行 `bash tools/build_variants.sh`，再执行 `bash tools/build_desktop.sh`，
产物为 `build/desktop/Codex Passport.app`。打包脚本会验证四种模式的内容寻址归档，再生成固件目录。
ARM64 应用包含 Python、USB/蓝牙依赖、esptool、已验证固件、OpenCC 和 CPU 引擎，
不含模型、账户令牌、个人配置或录音。
源码运行：`.local/transport-venv/bin/python bridge/desktop.py`。
图标源文件与来源说明见[资源目录](../assets/README.zh_CN.md)。修改源图后可在 macOS 上运行
`bash tools/build_desktop_icon.sh` 重新生成 ICNS；应用构建会同时打包 ICNS 和窗口使用的 PNG。

有限重试、扫描/配对/处理中停止、草稿保留、模型校验和单实例互斥。

提示音实际响度、麦克风拾音和真机按钮时序仍须刷机验收。
真实无线断线、新 Mac 配对、Gatekeeper、Intel、长时间待机和休眠唤醒需分别实测，主机测试不能证明。

## 桌面连接韧性（0.9.2）

额度由独立后台任务刷新，同一时间最多一次。界面和卡片状态请求直接读取缓存，慢额度接口不会阻塞它们；首次无缓存显示未知，失败后约 30 秒再试。发送仍等待一次强制最新额度检查，失败时保留草稿，不发送或入队。识别使用独立工作线程。

设备监控按采样年龄判断：15 秒以内且连接正常的样本，在草稿确认及转写期间仍是实时数据；录音／发送期间明确暂停，超过 15 秒标为旧值。旧固件未继续采样时不会误报实时。

| 失败阶段 | 提示与处理 |
| --- | --- |
| 扫描 | 检查 Mac 蓝牙开关及应用权限 |
| 权限 | 按系统原因提示授权或联系管理员，不反复配对 |
| 建立连接 | 检查卡片电源、距离及其他程序占用 |
| 身份验证 | 若 Mac 弹出配对框，输入卡片上的六位码 |
| 数据通道 | 通知订阅失败时重新连接 |
| 已连接后中断 | 自动重连原卡片；保留草稿，中断录音需重录 |

连接建立前连续失败三次后暂停；不会自动清除配对，也不显示原始系统错误中的设备标识。本批只需更新桌面应用；卡片草稿期间持续采样仍需第 015 批的 0.10.1 固件。
