# Mac 配套应用

原生窗口是 USB、蓝牙固件的新手入口。已有 Wi-Fi 命令行和独立离线固件保留，见
[模式选择](codex-modes.zh_CN.md)。本次更新无需重新烧录，其他想法见[优化清单](codex-improvements.zh_CN.md)。

## 首次使用

1. 使用 Apple 芯片、macOS 15 或更新版本的 Mac，安装 Codex 并登录已有 ChatGPT 账户。
   可用能力取决于 Codex 版本与账户；配套程序不提供订阅或无限额度。
2. 解压并打开 `Codex Passport.app`，可移到“应用程序”。打包版不需要 Python、ESP-IDF、
   CMake 或终端。本免费构建只有临时签名，未经 Apple 公证。其他 Mac 可能阻止打开，
   请按系统正常校验流程操作或联系管理员，不要关闭安全防护。
3. 查看 Codex/账户检查。可选 base 模型约 142 MB；选择已有的 `ggml-base.bin` 可直接
   复用而不复制，也可在窗口里下载。导入和下载均校验 SHA-256。没有模型时仍可查看
   时间、额度、对话，但暂不能语音输入。
4. 选择与已刷固件一致的 USB 或蓝牙并连接。USB 使用数据线；蓝牙需打开卡片，并按
   系统提示允许本程序访问蓝牙。首次配对在 Mac 输入卡片上的六位码。有多张卡片时，
   只打开目标卡片，或用命令行 `--address` 指定。
5. 保持应用和 Mac 运行。卡片息屏用功能键唤醒；独立电源键会切断供电，Mac 休眠也会暂停服务。

新版窗口/命令行程序只允许一份占用卡片。旧诊断脚本没有互斥锁，须检查草稿/队列后先关闭。
程序不会自动下载模型或调用付费识别服务。

## 恢复与数据

| 情况 | 行为／处理方式 |
| --- | --- |
| 蓝牙临时断线／卡片重新开机 | 只重连原卡片，重试间隔从 1 秒逐步延长到 15 秒。 |
| 录音中断 | 丢弃不完整音频，重连后重新录音。 |
| 已识别草稿／跟踪中的队列 | 在同一进程内跨重连、暂停保留，不自动发送或重复入队。 |
| 发送回执丢失 | 保留请求去重，结果不确定时在桌面确认，不自动重试。 |
| 蓝牙关闭／权限被拒 | 停止并指出系统设置或管理员处理方式，解决后再次连接。 |
| 配对失败 | 连续三次连接/配对失败后暂停。检查六位码；若 Mac 忽略过卡片，可在卡片连接说明页清除配对后重试。 |
| 协议不匹配 | 停止并提示使用匹配固件，应用不会烧录。 |
| 额度后台不可用 | 保持连接，定期重读状态并明确报错，不编造额度。 |
| 暂停 | 等待当前 RPC 完成后断开，保留草稿，丢弃未完成录音。 |
| 退出 | 有录音、未发送/不确定草稿或跟踪中的队列时提示。退出会清空内存状态，不会撤回已交给 Codex 的消息。 |

打包版数据位于 `~/Library/Application Support/CodexPassport`。`voice.json` 可引用校验过
的外部模型路径，不含对话内容。开发时可通过 `PASSPORT_DATA_DIR` 选择已有私有数据目录。
临时音频在转写完成或中断后删除。仍使用本机 Whisper base 加简体转换，窗口版不开放网络
监听端口。原有命令行使用方法与固件按键保持不变。

## 构建与验证

开发者在 `.local/transport-venv` 中安装 `bridge/desktop-requirements.txt`，并通过
`tools/bootstrap_bridge.py` 准备固定版本的 CPU 引擎。
执行 `bash tools/build_desktop.sh`，产物为 `build/desktop/Codex Passport.app`。
ARM64 应用包含 Python、USB/蓝牙依赖、OpenCC 和 CPU 引擎，不含模型、账户令牌、个人配置或录音。
源码运行：`.local/transport-venv/bin/python bridge/desktop.py`。

`tests/test_companion_desktop.py` 已接入门禁，覆盖设备身份、回执丢失、发送结果不确定、
有限重试、扫描/配对/处理中停止、草稿保留、模型校验和单实例互斥。
真实无线断线、新 Mac 配对、Gatekeeper、Intel、长时间待机和休眠唤醒需分别实测，主机测试不能证明。
